# Рабочие данные компьютерной версии

Данные импортируются отдельно от мобильной версии и исходной `/app/`. Файлы
`design-src/main-data.json`, `src/data/userSnapshot.json` и хранилище рабочей версии
этот экспорт не меняет.

Генерация из явно указанного свежего файла:

```sh
node scripts/export-online-data.mjs \
  --input /absolute/path/backup.json \
  --output online-src/working-data.json \
  --assets public/online/nom \
  --photos online-src/custom-photos
```

`--photos` необязателен. Он принимает каталог с исходными файлами пользователя,
названными по точному ID номенклатуры, например `urip40y.png`. Содержимое файла
проверяется по типу изображения; ссылка `blob:` из JSON сама по себе фотографией
не является. Отсутствующее исходное фото отражается в отчёте, без замены похожей
позицией.

Результаты:

- `working-data.json` — отдельный снимок для online. Исходные поля проектов и
  помещений сохранены вместе с преобразованными полями и `_main`.
- `working-data.json.source.json` — неизменённые байты исходного JSON.
- `working-data.json.report.json` — происхождение, счётчики, недоступные ссылки и
  фото, применённые поправки переноса и сверка всех строк расчётов.
- `public/online/nom/` — изображения с именами на основе ID, включая исходные фото.

Номенклатура связывается по `id`/`nid`, а не по названию. Ключ строки полотна —
`nid|roomId`, остальных строк — `nid`. Правки помещения находятся в `room.estEd`,
итоговые правки — в `estEd[projectId]`. В отчёте сравниваются количества, цены,
единицы и суммы до копейки с исходным `buildEst`, включая сохранённые цены и
правки сметы. Код завершения `2` означает расхождение расчётов.

Raw JSON и отчёт не размещаются в `public`. Публикация выполняется отдельно по
команде пользователя. Повторный запуск не должен использовать старый встроенный
снимок основной версии вместо свежей резервной копии.

## Данные после открытия онлайн-версии

Начальный импорт используется только при отсутствии сохранённого снимка. Изменения
оператора хранятся в браузере в отдельной IndexedDB-базе
`zamer.desktop.snapshots.v1`, store `snapshots`. Ключ рабочего пространства —
`zamer.desktop.working.v1`, демо — `zamer.desktop.v1`; они не смешиваются.
Загрузка и валидация завершаются до импорта расчётного движка. Снимок IndexedDB
имеет приоритет; если его ещё нет, переносится прежний raw JSON или gzip из
соответствующего localStorage-ключа. Эти ключи не удаляются. Старое приложение,
его база `magicapp_v2_4_db` и мобильные данные остаются независимыми. При
недоступности IndexedDB используется localStorage с прежним ограничением объёма.

Сохранение выполняется последовательной очередью с объединением ожидающих
изменений в последний полный снимок. Интерфейс различает ожидающую запись,
завершённую транзакцию и ошибку. При ошибке живые данные остаются в редакторе;
баннер позволяет повторить запись или скачать JSON. Закрытие страницы с
ожидающими или несохранёнными изменениями защищено предупреждением браузера.

«Настройки → Резервная копия» скачивает актуальный снимок, включая изменения,
которые пока не попали в хранилище. Восстановление проверяет выбранный файл и
заменяет данные текущей онлайн-версии после успешной записи. Если исходный снимок
не удаётся загрузить, приложение показывает восстановление, а не перезаписывает
его начальным импортом.

Браузеры и origin имеют отдельные хранилища: локальные адреса и опубликованный
сайт не синхронизируются. Облака нет; резервные JSON-файлы нужны для переноса и
восстановления после очистки данных браузера.

## Независимые расчёты · 2026-11-03

Каждое помещение хранит определения блоков и опций в `catalogSnapshot`, каждый
экземпляр пресета — состав, цены и все варианты в `presetSnapshot`. Изменение или
удаление общей номенклатуры и пресетов не меняет старые расчёты и их фотографии.
Удалённый пресет остаётся сохранённым выбором в расчёте.

При входе в редактор из проекта показывается актуальная общая запись.
«Сохранить» обновляет все использования выбранной номенклатуры либо экземпляры
выбранного `bid + pid` только в текущем проекте. «Назад» и «Отмена» оставляют
расчёт прежним. Изменения номенклатуры внутри редактора пресета применяются к
проекту после внешнего сохранения; внешняя отмена отменяет их вместе с пресетом.

Новые помещения, экземпляры и явно выбранные пресеты получают свежие копии
базы. Смена пресета затрагивает только выбранный экземпляр. Дублирование
сохраняет снимки и ручные значения, а дублирование проекта — также его
`estEd[projectId]`. Первичная фиксация сохраняет исходные количества, цены и
правки; совместимые правки количества остаются после явного обновления.
Единица `u` привязывает правку к исходной строке, исключая применение к строке
с другой единицей. Применение новой цены снимает соответствующую ценовую правку.

Готовые фотографии расчётов сохраняются без `photoSource` и `photoCrop`.
Повторяющиеся встроенные изображения объединяются в `_frozenImages` в снимке
IndexedDB и JSON-копии; при загрузке восстанавливаются обычные поля изображения.

При запуске все существующие проекты дополнительно фиксируются до изменений
общей базы; готовые снимки остаются прежними. Миграция использует текущие
доступные значения и не восстанавливает уже потерянную историю. Изменения
выполнены локально; публикация выполняется по отдельной команде пользователя.
