# Мобильный и планшетный прототип ЗАМЕРX

Актуальный снимок от 06.11.2026. В этой отдельной папке собран мобильный и планшетный прототип целиком: интерфейс приложения, калькулятор, ручной построитель и связанные функции. Это веб-прототип для переноса в React Native: HTML/CSS, JS-логика и Canvas. Нативную раскладку и жесты нужно реализовать в RN по приложенному ТЗ.

Папка самодостаточна: исходники, ресурсы и локальные зависимости сборки включены внутрь `mobile-prototype/`; файлы соседних версий из репозитория для просмотра и пересборки не нужны. Пакетные зависимости устанавливаются через `npm ci`.

## Быстро посмотреть без установки зависимостей

Из корня репозитория запустите:

```sh
cd mobile-prototype
python3 -m http.server 5177 --directory public
```

Откройте http://127.0.0.1:5177/design/ . Если порт занят, замените 5177 на свободный порт и в команде, и в адресе.
На компьютере сверху доступен выбор телефона/планшета и ориентации. На реальном устройстве используется адаптивная версия. Для прямого входа без оболочки предпросмотра: /design/app.html . Через file:// прототип открывать не нужно: ресурсы используют абсолютные пути /design/.

## Где редактировать

- public/design/ — уже собранный работающий прототип: index.html (оболочка просмотра), app.html (приложение), draw.js/draw.css (построитель), остальные бандлы, шрифты и изображения.
- src/design-bridge/drawEditor/editor.js — состояния, интерфейс, формы, жесты, камера, история и сохранение построителя.
- src/design-bridge/drawEditor/geometry.js — ограничения, решатель, площадь/периметр, инструменты и кривые.
- src/design-bridge/drawEditor/*.css — стили редактора, телефона и планшета.
- src/design-bridge/drawEditor/sketch-ruler.js, ruler-edge-pan.js, ruler-work-view.js — рисование по размерам, движение у края и рабочий масштаб.
- src/components/builders/operation-guide.* и measurement-tools.* — схемы параметров и последовательный ввод.
- src/design-bridge/draw-entry.js — вход редактора и интеграционный контракт.
- src/design-bridge/room-drawing-preview.js — миниатюра чертежа в калькуляторе.
- design-src/prototype.html — исходная база оболочки приложения. Для актуального результата её ОБЯЗАТЕЛЬНО пропускать через сборку: последующие изменения находятся также в scripts/design-*.mjs.
- design-src/interface.css, tablet.css, device-preview.* — общий интерфейс, адаптация планшетов и выбор устройства для просмотра.
- scripts/build-design.mjs и scripts/design-*.mjs — сборка и актуальные изменения шаблона. Сгенерированные public/design/* не являются основным местом правок.
- src/ — дополнительно включены зависимости, необходимые для пересборки этого прототипа.
- tests/ — регрессионные проверки построителя, миниатюры, планшета и выбора устройства.

## Пересобрать после изменений

Нужны Node.js/npm и доступ к npm при первой установке. Команды ниже выполняются из корня репозитория; если вы уже находитесь в `mobile-prototype`, повторный `cd` не нужен:

```sh
cd mobile-prototype
npm ci
npm run design
npm test
```

После сборки обновите страницу HTTP-предпросмотра. Сборка выполняется локально, ничего не публикует. Исходники и готовая статика включены вместе; node_modules, .git и настройки публикации не требуются и не включены.

## ТЗ и важные границы

- docs/ZAMERX_Manual_Builder_React_Native_Specification.pdf — основное ТЗ: 48 страниц, 25 разделов, 76 сценариев приёмки. По ручному построителю оно приоритетнее старых комментариев и исходной базы prototype.html. Согласованные функции, текущие ограничения и решения для RN разделены.
- docs/MOBILE_CEILING_BUILDER.md — описание текущего мобильного редактора и технических деталей.
- docs/TABLET_PROTOTYPE.md — адаптация всего прототипа для планшета.
- Пользовательские проекты и их корректировки смет в этой копии очищены; создайте тестовый проект через интерфейс. Каталог и настройки пресетов сохранены для просмотра вёрстки. Данные исходного рабочего проекта не изменялись.
- Ручной построитель работает на локальных ресурсах. PDF-экспорт сметы/договора и открытие PDF для обводки используют внешние библиотеки CDN и требуют интернета.
- Существующие ограничения (включая краткое появление необработанного шаблона при запуске) не считать исправленными размещением прототипа: они описаны в PDF. Это перенос текущего прототипа, а не гарантия отсутствия дефектов.
