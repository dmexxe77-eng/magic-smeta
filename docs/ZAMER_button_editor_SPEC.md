# ТЗ: Редактор кнопок (Zamer.pro)

Документ — спецификация фичи «Редактор кнопок» для онлайн-версии Zamer.pro.
Рядом лежит рабочий HTML-прототип `zamer_editor_prototype.html` — эталон логики и дизайна.
Прототип **не переносить в проект как есть**: это одностраничный HTML на ванильном JS.
Из него берётся модель данных, поведение и визуальный язык; реализация — в стеке проекта.

---

## 0. Контекст

В калькуляторе есть блоки (Полотно, Основной профиль, Доп. профиль, Светильники/люстры,
Линейное освещение, Шторы). В каждом блоке — набор кнопок-пресетов (MSD Evolution,
EUROKRAAB STRONG, Отсечка FOTON 80 …). Кнопка — это готовый набор номенклатур с правилами
расчёта количества.

Сейчас пресеты зашиты в коде. Редактор кнопок даёт пользователю (замерщику/владельцу)
создавать и менять их прямо в приложении.

---

## 1. Модель данных

### 1.1. Блок (категория)

```ts
type Block = {
  id: string;         // 'canvas' | 'main' | 'extra' | 'light' | 'track' | 'curtain' | 'cst_<timestamp>'
  label: string;      // 'Полотно', 'Основной профиль', …
  custom?: boolean;   // true — созданный пользователем блок (его можно удалить)
  order: number;
}
```

Шесть встроенных блоков удалять нельзя. Пользовательские — можно.

### 1.2. Кнопка (пресет)

```ts
type Preset = {
  id: string;
  blockId: string;
  name: string;
  param: {
    src: 'area' | 'perim' | 'manual';   // источник главного параметра кнопки
    unit?: 'м.п.' | 'шт' | 'м²';        // только при src='manual'
  };
  items: PresetItem[];
  hidden?: boolean;   // не показывать в калькуляторе (в редакторе видна полупрозрачной)
  order: number;
}
```

### 1.3. Позиция внутри кнопки

**Важно: позиции и опции объединены в один список.** Раздельных «Позиций» и «Опций» больше нет —
разница между ними была только в источнике количества, и теперь это поле `src` у каждой строки.

```ts
type PresetItem = {
  nomId: string;   // ссылка на номенклатуру в базе
  src: 'param' | 'area' | 'perim' | 'corn_all' | 'corn_in' | 'corn_out' | 'manual';
  order: number;
}
```

Цену и единицу **не дублировать** в пресет — тянуть из номенклатуры по `nomId`
(иначе «обновить цены» не работает). В прототипе они скопированы только ради простоты.

### 1.4. Источники количества (`src`)

| src        | Откуда количество                        | Значок | Цвет    |
|------------|------------------------------------------|--------|---------|
| `param`    | главный параметр кнопки (S / P / ручное N)| `×`    | #4F46E5 |
| `area`     | площадь помещения с чертежа               | `S`    | #4F46E5 |
| `perim`    | периметр помещения с чертежа              | `P`    | #0a84ff |
| `corn_all` | все углы чертежа                          | `∠`    | #ff9500 |
| `corn_in`  | внутренние углы                           | `∠`    | #16a34a |
| `corn_out` | внешние углы                              | `∠`    | #ff3b30 |
| `manual`   | **ручной ввод замерщика, по умолчанию 0** | `#`    | #8e8e93 |

### 1.5. Функция расчёта количества

```js
function qtyOf(instance, item, room) {
  // 1. Ручная правка в калькуляторе всегда главнее
  if (instance.overrides[item.id] !== undefined) return instance.overrides[item.id];

  switch (item.src) {
    case 'param':  return instance.paramValue;   // S, P или введённое N
    case 'manual': return 0;                     // ← ждём ввода замерщика
    case 'area':   return room.area;
    case 'perim':  return room.perimeter;
    case 'corn_all': return room.cornersIn + room.cornersOut;
    case 'corn_in':  return room.cornersIn;
    case 'corn_out': return room.cornersOut;
  }
}
```

`manual` = 0 — принципиально. Такая строка не увеличивает смету, пока замерщик не введёт число.

## 2. Экран «Редактор кнопок»

Вход: иконка ✎ среди чипов кнопок в любом блоке калькулятора. Открывается редактор,
уже позиционированный на этом блоке и на текущей выбранной кнопке.

### 2.1. Структура экрана сверху вниз

**1. Вкладки блоков** — горизонтальный скролл. В конце — вкладка `+ блок`
(создаёт пользовательский блок через диалог с именем). У выбранной пользовательской
вкладки появляется ✕ для удаления.

**2. Карточка «Кнопки блока»**
- чипы всех кнопок блока, выбранная — залита индиго;
- скрытые (`hidden`) — полупрозрачные (opacity .35);
- чип `+` — создать новую кнопку (сразу фокус в поле имени);
- перетаскивание чипов = порядок кнопок (long-press ~330 мс, затем drag);
- поле **Название кнопки** — правка вживую, чип обновляется по мере ввода;
- тумблер **«Показывать в калькуляторе»** — управляет `hidden`;
- кнопки **⧉ Дублировать** и **✕ Удалить кнопку**.

**3. Панель «Параметр кнопки»** (индиговая подложка, шапка списка позиций)
- сегменты: `S · с чертежа` / `P · с чертежа` / `Вручную`;
- при «Вручную» — выбор единицы: м.п. / шт / м²;
- подсказка внизу поясняет, что параметр умножает позиции с привязкой «× Параметр».

**4. Список «Позиции»**
- строка: название номенклатуры, цена/единица, чип источника, ✕;
- чип источника показывает текущий `src` (значок + подпись);
- тап по чипу → шторка выбора источника;
- `+ Добавить` в заголовке секции → шторка выбора номенклатуры из базы (поиск + группировка по брендам).

### 2.2. Шторка выбора источника количества

Семь вариантов перегружают список, поэтому они сгруппированы:

```
[выделенная плашка]  × Параметр кнопки · S — площадь с чертежа
ПРИВЯЗАТЬ К ЧЕРТЕЖУ
  S  Площадь чертежа · м²
  P  Периметр чертежа · м.п.
  ∠  Все углы чертежа
  ∠  Внутренние углы
  ∠  Внешние углы
В КАЛЬКУЛЯТОРЕ
  #  Ручной ввод · в смете по умолчанию 0
```

Выбор закрывает шторку. Текущий вариант помечен галочкой в цвете источника.

### 2.3. Умный дефолт при добавлении номенклатуры

- название содержит «внутрен» → `corn_in`
- «внешн» → `corn_out`
- «угл» → `corn_all`
- иначе → `param`

## 3. Что меняется в калькуляторе

### 3.1. Единый список позиций

Вместо двух секций «Позиции» и «Опции» — одна. У каждой строки перед количеством
цветной значок источника: `620 ₽/м.п. ×41,66`, `1 000 ₽/шт ∠14`, `2 500 ₽/шт #0`.
Замерщик видит, откуда взялась цифра.

### 3.2. Ручные строки

Пока `manual`-строка не заполнена, количество показывается как **пунктирный чип-приглашение**
с нулём (приглушённый, без заливки). После ввода — обычный чип. Сумма строки 0 ₽ и в итог
блока не идёт.

### 3.3. Галочка «Ко всем»

В шапке блоков **Полотно** и **Основной профиль**, между названием и суммой:
чекбокс + подпись «Ко всем». **По умолчанию выключен.** Включённый — зелёная галочка,
зелёная подпись, лёгкая зелёная подложка. Означает: выбранная кнопка применяется ко всем
помещениям объекта. Тап по галочке не должен сворачивать блок (`stopPropagation`).

### 3.4. Иерархия названий

- Название блока (ПОЛОТНО, ОСНОВНОЙ ПРОФИЛЬ) — 12,5px / 800 / #1e2530, uppercase. Это главный ориентир.
- Имя выбранной кнопки в свёрнутом виде — мелким серым в скобках.
- Кнопки `+ Доп. полотно`, `+ Доп. профиль` и т. п. — **тихие серые строки без плашек**,
  10,5px / 700 / #9aa0b2, прозрачный фон. Не должны конкурировать с названиями блоков.

### 3.5. Скрытые кнопки

Кнопка с `hidden` не появляется среди чипов калькулятора. Если скрыли ту, что была выбрана в
блоке, — блок переключается на первую видимую кнопку.

## 5. Персистентность

Кнопки и блоки должны переживать перезагрузку страницы.

- Минимум для теста: `localStorage`, ключ `zamer.presets.v1`, версионированная схема.
- Правильнее: хранилище на бэкенде, привязанное к пользователю (если в проекте уже есть авторизация — использовать её).
- Обязательно: экспорт/импорт JSON всей конфигурации (блоки + кнопки + позиции). Это способ
  перенести настройки между устройствами и восстановить после сброса.

Формат экспорта:

```json
{
  "version": 1,
  "blocks": [...],
  "presets": [...]
}
```

## 6. Критерии приёмки

- [ ] Из калькулятора по ✎ открывается редактор на нужном блоке и кнопке.
- [ ] Создание, переименование, дублирование, удаление кнопки работают и сразу видны в калькуляторе.
- [ ] Порядок кнопок меняется перетаскиванием и сохраняется.
- [ ] Тумблер видимости прячет кнопку из калькулятора, в редакторе она остаётся полупрозрачной.
- [ ] Позиции и опции — единый список; у каждой строки виден источник количества.
- [ ] Смена параметра кнопки (S / P / вручную) пересчитывает все строки с `× Параметр`.
- [ ] Строки с `#` в калькуляторе стартуют с нуля и не увеличивают смету.
- [ ] Правка количества в калькуляторе не сбрасывается при пересчёте соседних строк и не теряет фокус ввода.
- [ ] Галочка «Ко всем» есть только в Полотне и Осн. профиле, выключена по умолчанию, не сворачивает блок.
- [ ] Пользовательский блок создаётся, появляется в калькуляторе строкой `+ Название`, удаляется вместе со своими кнопками и экземплярами.
- [ ] Конфигурация переживает перезагрузку; экспорт/импорт JSON работает.
- [ ] Итог сметы совпадает до копейки при одинаковых входных данных.

---

## 7. Чего не делать

- Не переписывать калькулятор целиком — редактор добавляется рядом, расчётная часть трогается
  минимально (единый список позиций + `qtyOf`).
- Не копировать ванильный JS из прототипа — переписать на компоненты проекта.
- Не дублировать цены номенклатур внутри пресетов.
- Не заводить статус/поля, которых нет в этом ТЗ, без согласования.
- Не менять существующую схему хранения заказов без миграции.
