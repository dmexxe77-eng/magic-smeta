# ZAMER.PRO — мобильное приложение. Handoff для разработчика

Пакет для интеграции дизайна в React Native (Expo Go SDK 57). Версия 6 от 08.09.2026:
- Калькулятор: новый блок «Доп. опции помещения» в начале, перед «Полотно». Глобальный список ROOM_OPTS[] = {id, n (имя номенклатуры), p, u, m, src}; у помещения room.opts[id]=true/false (галочка своя в каждом помещении), room.optQ[id] — количество для src='manual' (inline-поле, при значении >0 галочка ставится сама). Отмеченные опции попадают в смету: q = optQty(src, geom) — area/perim/angles/inner/outer/manual; материал/работа по флагу m.
- Экран «Опции помещения» (optEd, чип «Настроить» в шапке блока): одна строка на опцию — имя позиции (тап → выбор из базы номенклатур, одиночный выбор, target:'opt'), чип параметра «× P» (тап → шторка «Что умножать»: S, P, все углы, внутр., внешн., вручную), ×. «+ Добавить из базы» сразу открывает базу; пустые пункты удаляются при выходе.
- В блоках убраны подписи «из чертежа / вручную» у S и P.
Версия 5:
- Навигация: нижний таб-бар из 5 вкладок — Главная (dash) · Проекты · [+ Создать] · Календарь · Аналитика. Аккаунт — через аватар в шапке Главной (экран account с кнопкой «назад»).
- Новый экран Главная (dash): плитки-сводки (В работе / Долги / Заявки / Сдано), ближайшие события на 7 дней, «Требуют внимания» (заявка без замера, расчёт не отправлен, монтаж завершён + долг, договор без даты монтажа). Три варианта раскладки — tweak dashLayout: a «Сводка», b «Сегодня», c «Список»; переключатель сверху экрана для выбора.
- Карточка проекта: свой таб-бар — Смета (PDF) · Договор · [Калькулятор/Замер] · Приход · Расход. Кнопки из тела карточки убраны; в карточке остались сводка (с расходами/прибылью и списком операций), события + «Назначить событие», данные клиента.
- Проекты: поиск по названию / клиенту / адресу / дизайнеру (state.pq), работает вместе с фильтром статусов.
Версия 4: монтаж в несколько этапов (installs[]), статус «В работе» с первого до последнего этапа. Версия 3: 6 статусов с автопереходами по событиям и календарю, Календарь (вкладка) и события (Замер/Встреча/Монтаж/Другое, монтаж на N дней), шторка события с выбором объекта, количество у каждой позиции (авто + ручной ввод), свой % корректировки, тёмная тема, редактор номенклатур, Аккаунт/Профиль/Аналитика. Открой `prototype.html` в браузере — это интерактивный прототип со всей логикой: кликабельны все экраны, смета пересчитывается вживую. Он и есть источник истины по поведению и визуалу.

Файлы:
- `prototype.html` — самодостаточный прототип (работает офлайн). Внутри в `<script data-dc-script>` — вся бизнес-логика на JS (пресеты, расчёт сметы, геометрия) — переносится в RN почти без правок.
- `README.md` — этот документ: токены, экраны, компоненты, логика.
- `screens/` — скриншоты.

Tweaks в прототипе (панель справа в браузере): `platform` (ios / android / ipad / android-tablet), `startScreen`, `measureInput` (keypad / native).

### Estimate — шторка «Смета» (92% высоты)
- Сегмент: «Помещение» / «Все помещения».
- Разделы МАТЕРИАЛЫ (accent) и РАБОТЫ (success): название · чип кол-ва · «ед ×» · чип цены · сумма. Тап по чипу — инлайн-инпут; правка сохраняется в проекте (estEd по ключу позиции).
- Низ: итог по выбранному scope + «Экспорт».

### Export — шторка «Экспорт сметы»
- Тип сметы (radio-карточки): Общая · Общая + чертежи · По помещениям.
- Столбцы (чипы): # Название Кол-во Ед. Цена Итого.
- Корректировка: чипы −15 … +15 % + поле «свой %» (flex 1.3, decimal, −90…300, шаг 0.1; при нестандартном значении рамка warning #FF9F0A / фон #FFF3E0). Под ней чекбокс «Показывать корректировку в смете» (exp.showPct, default true; при 0 % — opacity .5): включён — в PDF отдельная строка «Скидка/Наценка N %» и итог до/после; выключен — корректировка зашита в цены позиций, клиент видит только итог. Карточка с итогом после корректировки.
- «Скачать PDF» (primary) · «Отправить клиенту» → WhatsApp / Telegram / Почта / Ссылка. После экспорта статус order → estimate.

### AddRoom — способ построения
- Три карточки: Вручную (primary) · Обводка чертежа (PDF/фото) · Распознать эскиз (ИИ). Компаса нет.

### Manual — ручное построение
- Шапка: назад · имя помещения (инлайн-инпут) · «Выровнять» (округление до 5 см).
- Чертёж SVG: полигон, активная сторона подсвечена accent 4px, подписи длин на рёбрах (активная — залитая accent), буквы вершин A, B, C…; ниже S / P / углы.
- Лента сторон «AB 3,00» (активная — залита accent). Карточка «Сторона AB · 3,00 м» с кнопками «+ угол» (вставить вершину после) и «×» (удалить, минимум 3).
- Клавиатура 4×4: 1 2 3 ⌫ / 4 5 6 [Далее — accent, на 3 строки] / 7 8 9 , / 0. Ввод сразу меняет длину стороны (mbSide: масштабирует ребро, сдвигая остальные вершины).
- Низ: «Добавить в расчёт» (ink) / «Сохранить контур».
- Tweak `measureInput=native` — вместо клавиатуры список сторон с системными инпутами.

### EventSheet — шторка события
- Заголовок «Новое событие» / «Событие». Поле «Объект» 48px (точка статуса + название, chevron): тап раскрывает список проектов с поиском (#F7F7FC, строки 44px) и «+ Новый проект». Из календаря объект не выбран (рамка warning, «Сначала выберите объект»), из карточки — подставлен.
- Тип: 4 чипа 38px (Замер / Встреча / Монтаж / Другое), активный залит цветом типа. Подсказка под типом.
- Календарь месяца 38px-ячейки в цвете типа; для монтажа подсвечен весь диапазон; точки — чужие события; предупреждение «В этот день уже монтаж: …».
- Время: два select (часы 07–21, минуты 00/15/30/45) 64×40, подпись «Начало первого дня / Приезд на объект / Начало встречи».
- Только Монтаж: Длительность — степпер «− N +» (1–90, ручной ввод) + подпись «12 дней · 1 неделя 5 дней» и диапазон дат; быстрые чипы 1·2·3·5·7·14; Бригада — чипы.
- Не монтаж: поле Заметка.

## 3a. Логика статусов (реализовать как чистую функцию + триггеры)

Статусы переключаются событиями и календарём; вручную — только «Отказались» (любой можно переопределить в шторке, с пометкой «изменён вручную»).
1. order Заявка — при создании.
2. estimate Расчёт готов — скачан PDF или смета отправлена (из order). Дальше экспорт статус не двигает.
3. contract Договор подписан — из order/estimate при: первом приходе (`ops.kind='in'`) или назначении монтажа (`installDate`). Расход статус не меняет.
4. install В работе — производный от календаря: status ∈ {contract, install} и дата начала ПЕРВОГО этапа ≤ today → install; иначе (все этапы в будущем / монтаж снят) → contract. Между этапами проект остаётся «В работе». Пересчитывать при каждом рендере/фокусе приложения (`syncStatuses()`).
5. done Выполнен — status=install, конец ПОСЛЕДНЕГО этапа (max(date + days − 1)) ≤ today и после прихода paid ≥ сумма сметы − 0.5. Календарь дальше не влияет.
6. declined Отказались — вручную. Финансы закрыты.
Финансы (приход/расход) доступны во всех статусах кроме declined.

## 4. Логика (перенести из `prototype.html`, секция `<script data-dc-script>`)

- `calcPoly(pts)` — площадь (шнурок Гаусса) и периметр. `angles(pts)` — углы вершин, снап к 90/270 при |Δ|<15°. `geom(v)` → `{a, p, inn, out, angs}`.
- `PRESETS[blockId][]` — кнопки: `{id, name, items:[{n, p, u, m, src, k, mult}]}`; `m:1` — материал (иначе работа); `src` — источник количества; `k` — норма; `mult` — кратность.
- `instLines(bid, inst, qty, g)` — строки позиции с количеством по `src` и применением нормы/кратности; `inst.off[name]` — выключенные позиции.
- `subP(room)` — сумма м.п. экземпляров доп. профиля/штор с флагом `subP` — вычитается из P основного профиля. `singleQty` — количество для Полотна/Профиля (ручное `qtyO` приоритетнее).
- `est(rooms, edits)` — агрегация: материалы полотна — по помещениям (ключ `name|roomId`), остальное — суммируется по названию; `edits[key] = {q, p}` — ручные правки из шторки «Смета». Возвращает `{mats, works, mt, wt, total}`.
- `room.extraItems[]` — доп. позиции `{id, n, p, u, m, qty}`.
- `NOM[]` — база номенклатур `{n, p, u, m, br, mult?, note?, pInst?, pCost?}` (br — раздел/бренд; pInst — цена монтажнику; pCost — себестоимость). Имя `n` — ключ связи с позициями кнопок: правка в NomItem применяется ко всем `PRESETS[*].items` с этим именем.
- `inst.iq[name]` — ручное количество позиции внутри экземпляра кнопки (override авто-расчёта; для src 'manual' — единственный источник).
- `project.installDate/installTime/installDays/installCrew` — монтаж; `project.events[]` — прочие события; `events()` разворачивает монтаж в N дней (`install:true, first`).
- `exp.pct` — любое число (−90…300), `exp.showPct` — показывать корректировку в PDF отдельной строкой (true) или зашить в цены (false).
- `profile` — настройки аккаунта `{name, company, phone, email, city, legal, inn, bank, contractPhone, site, vat, notif:{tg,push,email}, bio, pin}`; `plan` — 'pro' | 'free'.
- Модель проекта: `{id, name, client, phone, address, designer, notes, status, date, paid, rooms[], ops[]}`; помещение: `{id, name, v:[[x,y]…], on, canvas:{pid,off,qtyO}, main:{…}, extra[], light[], track[], curtain[], extraItems[]}`; экземпляр: `{id, pid, qty, subP?}`.
- Форматирование: `F(n)` — пробел между тысячами, запятая — десятичный разделитель, до 2 знаков без хвостовых нулей; `RUB(n)` = `F(n)+' ₽'`.
