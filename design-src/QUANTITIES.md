# Количество в мобильном калькуляторе `/design`

Обновлено: 2026-10-29. Этот документ уточняет старые разделы README о «Параметре кнопки».
Изменения относятся к мобильной версии `/design`; интерфейс основной версии приложения не меняется.

## Что видит пользователь

- В каждой карточке выбран один пресет и задано своё количество. «Добавить» создаёт ещё одну карточку того же типа блока с независимыми значениями.
- Источник количества задаётся у типа блока: площадь чертежа (`area`), периметр (`perim`) или ручной ввод (`manual`). Площадь использует м², периметр — м.п.; для ручного ввода выбирается единица.
- Новый блок создаётся через редактор кнопок: название → источник → единица → позиции пресета. Свой блок можно настроить повторно.
- У позиции пресета доступно «Общее количество» по умолчанию, отдельная геометрия (площадь, периметр, все/внутренние/внешние углы) или «Ввести отдельно».
- Количество блока и любой позиции можно переопределить в калькуляторе. Сброс возвращает вычисление из источника; для ручного источника поле становится пустым.
- Редактор оформлен по iPhone-версии: настройки пресета открываются нижней панелью. «Сохранить» применяет черновик, «Закрыть» и стрелка назад отменяют его. Удаление архивирует пресет, сохраняя существующие сметы.
- «Норма» у позиции задаёт расход на одну единицу основного количества блока: 15 м.п. × норма 10 = 150 шт. Применение нормы выбирает «Общее количество» вместо прежней привязки к углам или отдельного ввода и убирает прежнее округление до упаковок. Подпись общая: «На 1 единицу основного количества». Пример расчёта использует единицу блока и единицу позиции. Явный выбор другого источника сбрасывает норму до 1.
- «Список» хранит несколько номенклатур в одной строке. В редакторе раскрывается компактный список под позицией: галочка задаёт вариант по умолчанию, крестик удаляет вариант, «Добавить вариант» открывает номенклатуру и возвращает к той же раскрытой строке. Последний вариант удалить нельзя. В калькуляторе стрелка раскрывает варианты прямо под строкой, без модального окна; цена, единица и вид материала/работы берутся у выбранного варианта. Выбор отдельный для каждой карточки.
- При входе в калькулятор все блоки свёрнуты. Выбранные пресеты видны синим с количеством и суммой; опции помещения и доп. позиции раскрываются отдельно.

## Данные и расчёт

| Уровень | Поля и назначение |
| --- | --- |
| Тип блока | `BLOCKS[*].source`, `.unit`: настройки для новых карточек |
| Карточка | `.pid`: один выбранный пресет; `.qty`: ручное количество повторяемого блока |
| Одиночный блок | `.qtyO`: ручное количество существующих блоков «Полотно» / «Основной профиль» |
| Снимок настроек | `.qdef = {source, unit}`: источник и единица конкретной карточки |
| Позиция пресета | `.src`: источник; `.k`: норма; `.mult`: кратность |
| Позиция карточки | `.iq[название]`: итоговое ручное количество; `.off[название]`: отключение позиции |
| Варианты строки | `.variants = [{n, p, u, m}, …]`: первый вариант выбран по умолчанию |
| Выбор карточки | `.variants[исходное название строки]`: название выбранного варианта; ключ строки для `iq` / `off` остаётся стабильным |

`src` без отдельного источника берёт количество блока. Затем применяется норма `k`; для штук результат нормы округляется вверх. Кратность `mult` округляет положительное количество вверх до ближайшего кратного. Значение из `iq` уже итоговое: норма и кратность повторно не применяются.

Отсутствие количества (`null` / нет поля) отличается от явного `0`: ноль сохраняется как ручное значение и не включает автоматический расчёт. Без чертежа геометрия неизвестна, а не равна нулю. Отрицательные и некорректные значения не принимаются.

Для основного профиля сохранено вычитание отмеченных длин доп. профиля и карниза из автоматического периметра. Ручное `main.qtyO` считается окончательным значением, повторного вычитания нет.

При сохранении настроек существующего своего блока форма добавляет прежние `source` / `unit` в `qdef` карточек, у которых снимка ещё нет. Уже сохранённые снимки не заменяются. Новые карточки получают новые настройки типа блока.

## Где менять

- `src/design-bridge/quantity-model.js` — чистые функции количества, вычитаний и строк сметы.
- `scripts/design-quantities.mjs` — `quantitiesTemplate`, интерфейс карточек, редактор источников, форма своего блока и подключение модели к смете.
- `scripts/design-preset-editor.mjs` — редактор, черновик, настройки, норма, списки и выбор варианта в калькуляторе.
- `scripts/design-calculator.mjs` — оформление калькулятора и независимое сворачивание разделов.
- `src/design-bridge/design-storage.js` и `scripts/design-storage.mjs` — проверка снимка, загрузка и автосохранение состояния `/design`.
- `scripts/build-design.mjs` — сборка прототипа из `design-src/prototype.html`.
- `tests/design-runtime.mjs` — тестовый запуск четырёх частей логики: `main-data.js`, `quantity.js`, `storage.js` и встроенного `data-dc-script`.
- `tests/design-quantity-model.test.mjs`, `design-storage.test.mjs`, `design-integration.test.mjs`, `design-export.test.mjs` и `design-e2e.mjs` — проверки модели, хранения, экспорта и пользовательского сценария.

Порядок преобразования шаблона: основные данные (`patchTemplate`) → вырезы (`holesTemplate`) → `quantitiesTemplate` → `storageTemplate` → `presetEditorTemplate` → `calculatorTemplate` → оформление (`brandTemplate`).

## Хранение

Автосохранение использует `localStorage` с ключом `zamer.design.v1`: блоки, пресеты, номенклатуры, опции помещений, проекты и правки сметы. Оно действует в текущем браузере на текущем устройстве и origin; это не облачная синхронизация. Другой домен или порт имеет отдельное хранилище.

## Сборка и проверка

Из корня `Проект/app`:

```sh
npm run design
npm test
npm run test:quantities
npm run dev
```

В другом терминале при работающем сервере: `npm run test:e2e`.
По умолчанию E2E открывает `http://127.0.0.1:5173/design/index.html` через установленный Google Chrome. Адрес меняется через `DESIGN_URL`, канал браузера — через `PLAYWRIGHT_CHANNEL`. Для Vite используйте путь `/design/index.html`.

`npm run design` генерирует отслеживаемые Git файлы `public/design/`, включая `index.html`, `quantity.js` и `storage.js`. После правок исходников пересоберите их и включите результат в изменение.

Интеграционные проверки сравнивают суммы всех 19 существующих проектов с эталонами `design-src/main-data.json`. Отдельные сценарии проверяют черновик, отмену, норму, списки вариантов, сохранение старых смет при архивировании и сворачивание разделов.
