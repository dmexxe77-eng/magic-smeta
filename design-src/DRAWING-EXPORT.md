# Чертежи в экспорте сметы

Общий генератор: `src/utils/estimate-drawing.js`. Он не зависит от DOM, Canvas,
React или состояния приложения. Веб-просмотр, PDF и будущий React Native клиент
должны использовать его, а не рассчитывать контур и размеры заново.

## Данные помещения

```js
const room = {
  name: 'Кухня',
  v: [[0, 0], [4, 0], [4, 3], [0, 3]],
  holes: [[[1, 1], [2, 1], [2, 2], [1, 2]]],
};
```

Координаты `v` и `holes` — в **метрах**, в одной системе координат. Используется
итоговый контур `v`, а не промежуточный `draw.base`. Вырезы вычитаются из площади
и добавляются к периметру. Подписи сторон — сантиметры, округлённые до целого;
площадь и периметр считаются по исходным координатам без этого округления.
В заголовке площадь показана в м², периметр — в метрах, до двух знаков после запятой.

## Общий интерфейс

- `roomDrawingSvg(room, { compact })` — самостоятельная строка SVG с размерами,
  `viewBox`, сеткой, контуром и подписями. Не нужны внешние стили или изображения.
- `roomDrawingLayout(room, { compact })` — модель расположения элементов для
  прямого нативного рендеринга. Не изменяет входные данные.
- `roomDrawingHtml(room, { compact })` — веб-карточка с названием, метриками и
  тем же SVG. Пустой или некорректный контур показывает «Чертёж не добавлен».

Компактный чертёж: 340 × 160; полный: 688 × 280. Масштабировать нужно целиком,
с сохранением пропорций. Подписи не соединяются с гранями выносными линиями.

В модели `area` — м², `perimeter` — метры. `rings`, `vertices`, позиции и
ограничивающие прямоугольники `labels` уже преобразованы в единицы SVG
(`width` × `height`), не в метры. У подписи есть `ringIndex`, `edgeIndex` и
`lengthCm`, связывающие её с исходной стороной. Пустой `path` означает отсутствие
корректного чертежа.

## Подключение в React Native

Чистый генератор переносится вместе с модулем; браузерный `estimate-entry.js`
импортировать в React Native не нужно. Для отображения SVG-строки подходит
[`SvgXml` из react-native-svg](https://github.com/software-mansion/react-native-svg/blob/main/USAGE.md#use-with-xml-strings):

```jsx
import { SvgXml } from 'react-native-svg';
import { roomDrawingSvg } from '../utils/estimate-drawing.js';

function RoomPlan({ room, width }) {
  const xml = roomDrawingSvg(room, { compact: true });
  if (!xml) return null; // В карточке показать состояние «Чертёж не добавлен».
  return <SvgXml xml={xml} width={width} height={width * 160 / 340} />;
}
```

SVG использует явные атрибуты и белые подложки подписей. Он не рассчитывает
размеры через браузерные шрифтовые метрики и не зависит от CSS `paint-order`.

## Создание PDF

`estimateHtml()` задаёт состав сметы и использует общий генератор чертежей:

- `type: 'draw'` — общая смета, затем отдельные листы с чертежами по два в ряд;
- `type: 'rooms'` — чертёж перед расчётом каждого помещения, следующее помещение
  начинается с новой страницы;
- общие позиции без привязки к помещению не получают выдуманный чертёж.

Веб-адаптер `src/utils/pdf.js` использует DOM, html2canvas и jsPDF. Он не является
React Native адаптером. При подключении нативной печати следует сохранить общие
расчёты, SVG и модель документа, а создание файла и отправку подключить через
API выбранной нативной библиотеки. Относительные пути `/design/nom/...` для фото
номенклатуры необходимо заменить на доступные встроенные изображения/data URI.

Нативный движок должен учитывать разрыв перед помещением/приложением,
неделимость карточки чертежа и связь заголовка таблицы с первой строкой. Веб-
атрибуты `data-pdf-*` обрабатывает только веб-адаптер; сами по себе они не
управляют нативной пагинацией.

## Проверка при подключении нативного приложения

В репозитории пока нет React Native сборки. Генератор проверяется в Node и
браузерном PDF; проверка на устройстве остаётся частью нативного подключения.
На iOS и Android проверить сложный контур с короткими уступами, вырезы, длинное
название, оба размера карточки и многостраничный экспорт. Размеры сторон,
площадь, периметр и итог сметы должны совпадать с веб-версией.
